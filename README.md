# mobile-ux-audit: аудит мобильной версии сайта

Набор скриптов на Node.js и Playwright, который цифрами показывает, что мешает покупателю на телефоне.
Сделан вместе с Claude Code и использовался в платном аудите интернет-магазина на Nuxt.

## Что проверяет

| Скрипт | Что делает |
|---|---|
| `scan.mjs` | LCP и CLS с виновниками, длинные задачи, блоки шире экрана, мелкие цели нажатия (24 px по WCAG 2.5.8 и 44 px по Apple), мелкий текст, поля, из-за которых iOS увеличивает страницу, контраст, картинки без размеров и слишком тяжелые для своего места, плашка cookie, проверка доступности axe-core |
| `report.mjs` | отчет в Markdown из `scan.json` |
| `lh.mjs` | Lighthouse с эмуляцией телефона, несколько прогонов |
| `seo.mjs` | 15 проверок поисковой базы: мета-теги, разметка, robots, sitemap, страница 404, https |
| `quick.mjs` | быстрая проверка одного адреса |
| `dokazatelstva.mjs` | скриншоты на телефоне, где проблемное место обведено, а в подписи живой замер |

## Запуск

```bash
npm install          # ставит и Chromium для Playwright
node scan.mjs out https://example.com --tormoz
node report.mjs out
```

`--tormoz` включает торможение сети и процессора, как у среднего телефона. Без него на домашнем интернете
числа получаются оптимистичными. Виды экрана: `--views=phone,phone-small,tablet,pc`.

## Как проверял сам инструмент

- `tap.test.mjs` (`npm test`): страница с заранее известным ответом. На ней сканер обязан найти ровно
  заложенные нарушения по целям нажатия, ни больше ни меньше.
- Первая версия считала блок «вылезающим за экран», даже когда его обрезал родитель с `overflow: hidden`
  (слайды карусели). Это было ложное срабатывание, теперь проблемой считается только то, что не обрезано предком.
- Замеры скорости заметно плавают, поэтому `lh.mjs` гоняет несколько прогонов и считает медиану.
- В `recepty.md` собраны рецепты исправлений и выводы из работы на настоящем сайте.
