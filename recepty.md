# Рецепты правок мобильной версии

Готовые решения под находки сканера. Код проверять на копии, потом показывать «было / стало».
Пороговые значения и обоснование — `manager/znaniya/skorost-i-dostupnost.md`.

## 1. Текст на баннере обрезается по краям
Причина: текст вшит в картинку фиксированных пропорций, на узком экране она обрезается.
```html
<div class="hero">
  <img class="hero__img" src="/img/hero-1600.webp"
       srcset="/img/hero-800.webp 800w, /img/hero-1200.webp 1200w, /img/hero-1600.webp 1600w"
       sizes="100vw" width="1600" height="900" alt="" fetchpriority="high" decoding="async">
  <div class="hero__text"><h2>Заголовок предложения</h2><a class="btn" href="/catalog/">Смотреть</a></div>
</div>
```
```css
.hero{position:relative;overflow:hidden}
.hero__img{width:100%;height:clamp(240px,56vw,520px);object-fit:cover;object-position:70% center}
.hero__text{position:absolute;inset:auto 0 0 0;padding:16px;background:linear-gradient(transparent,rgba(0,0,0,.65))}
@media (max-width:640px){.hero__text h2{font-size:clamp(20px,5.4vw,28px);line-height:1.15}}
```
Текст отдельным слоем — он всегда читается; точку фокуса картинки подбирать под сюжет.

## 2. Плашка cookie закрывает товары
Ставить полосой внизу, не поверх контента, и обязательно с кнопкой отказа (в России cookie — персональные данные).
Готовый вариант с Метрикой после согласия лежит в моем наборе инструментов для переноса сайтов.
Чтобы полоса не перекрывала последний блок:
```css
body{padding-bottom:var(--cc-h,0px)}
```
и в скрипте после показа: `document.body.style.setProperty('--cc-h', bar.offsetHeight + 'px')`.

## 3. Мелкие цели нажатия
```css
.menu a, .footer a, .icon-btn{min-height:44px;min-width:44px;display:inline-flex;align-items:center}
/* если нельзя увеличить саму ссылку — расширяем область нажатия */
.small-link{position:relative}
.small-link::after{content:"";position:absolute;inset:-12px;}
```
Минимум по стандарту — 24×24 px, комфорт — 44 px (Apple) и 48 dp (Google).

## 4. Прыгающая вёрстка из-за картинок
Каждой картинке — `width` и `height` или `aspect-ratio`:
```css
.card__img{width:100%;aspect-ratio:3/4;object-fit:cover}
```
Для карточек списка — `loading="lazy"`, для картинки первого экрана — наоборот, `fetchpriority="high"` без lazy.

## 5. Тяжёлые фото товаров
Если картинки лежат на своём сервере: набор размеров и WebP/AVIF.
```html
<img src="/img/p-400.webp" srcset="/img/p-200.webp 200w, /img/p-400.webp 400w, /img/p-800.webp 800w"
     sizes="(max-width:640px) 45vw, 240px" width="400" height="533" loading="lazy" alt="Название товара">
```
В Nuxt — `<NuxtImg>` с модулем `@nuxt/image`; для картинок с чужого домена домен нужно добавить
в настройки IPX, иначе оптимизация не применяется.

## 6. Закреплённая шапка занимает много экрана
Сжимать при прокрутке. Без JS:
```css
@supports (animation-timeline: scroll()) {
  .header{animation:shrink linear both;animation-timeline:scroll();animation-range:0 160px}
  @keyframes shrink{to{height:56px;padding-block:6px}}
}
```
Запасной вариант, работающий везде:
```js
const h = document.querySelector('.header');
addEventListener('scroll', () => h.classList.toggle('is-small', scrollY > 120), { passive: true });
```

## 7. Цена и кнопка ниже сгиба в карточке товара
Закреплённая полоса покупки, когда основная кнопка ушла с экрана:
```js
const btn = document.querySelector('.buy');
const bar = document.querySelector('.buybar');
new IntersectionObserver(([e]) => bar.classList.toggle('is-shown', !e.isIntersecting), { threshold: 0 }).observe(btn);
```
```css
.buybar{position:fixed;left:0;right:0;bottom:0;transform:translateY(100%);transition:transform .2s;
  display:flex;gap:12px;align-items:center;padding:10px 16px;background:#fff;box-shadow:0 -6px 18px rgba(0,0,0,.12)}
.buybar.is-shown{transform:none}
.buybar .btn{min-height:48px;flex:1}
```
Клиенту говорим честно: приём часто даёт прирост, но процент обещать нельзя — проверим на его трафике.

## 8. Поля формы, из-за которых iOS увеличивает страницу
```css
input, select, textarea{font-size:16px}
```
И не запрещать масштабирование: `<meta name="viewport" content="width=device-width, initial-scale=1">` без
`user-scalable=no` и `maximum-scale=1`.

## 9. Горизонтальная прокрутка
Ищем виновника сканером (`overflow`), потом:
```css
html,body{overflow-x:clip}           /* лечение симптома, не причины */
.grid{grid-template-columns:repeat(auto-fit,minmax(min(100%,220px),1fr))}
.table-wrap{overflow-x:auto;-webkit-overflow-scrolling:touch}
img,video,table{max-width:100%}
```
Сначала чиним причину (жёсткие ширины, длинные слова, таблицы), `overflow-x` — в последнюю очередь.

## 10. Низкий контраст
Проверять пары «текст / фон» сканером. Норма: 4,5:1, для крупного и жирного — 3:1.
Правим цвет текста, а не только прозрачность: `opacity` уменьшает контраст сильнее, чем кажется.

## 11. Увеличить область нажатия, не трогая внешний вид

Задача: ссылка или значок выглядит маленьким (телефон в подвале, иконка 24 px), а нажимать
в него неудобно. Менять размер шрифта нельзя — поедет дизайн.

Решение: невидимая область нажатия псевдоэлементом. Размер цели — это то, что принимает касание,
а не то, что нарисовано.

```css
/* Область нажатия 44×44 вокруг центра элемента, вид не меняется */
.tap-44 {
  position: relative;
}
.tap-44::after {
  content: "";
  position: absolute;
  top: 50%;
  left: 50%;
  translate: -50% -50%;
  width: max(100%, 44px);
  height: max(100%, 44px);
}
```

Для списка ссылок в столбце (подвал, меню) проще увеличить сам элемент отступами.
Тут важно не пытаться «вернуть» прежнюю высоту отрицательным отступом: так соседние
области нажатия наедут друг на друга, и палец начнёт попадать не туда.

```css
.footer-menu a {
  display: block;
  padding-block: 13px;   /* 18px текста + 26px отступов = 44px */
}
.footer-menu {
  /* компенсируем не отступами элементов, а общим зазором списка */
  gap: 0;
}
```

Подвал станет выше — это нормальная плата. Если высота критична, оставляем текст как есть
и добавляем область псевдоэлементом, ограничив её высотой доступного зазора.

**Важно:** соседние невидимые области не должны перекрываться, иначе палец будет попадать не туда.
Проверять сканером: `под44` должно уменьшаться, а число элементов оставаться тем же.

**Проверено в браузере 24.09.2026** (Playwright, экран 390 px): у ссылки с высотой текста 19 px
область нажатия стала 141×44, у значка 24×24 — ровно 44×44. Касание на 10 px ниже текста
по-прежнему попадает в ссылку. То есть приём работает, а не просто выглядит правдоподобно.

Нормы: 24×24 px — минимум по WCAG 2.5.8 (AA), 44×44 — рекомендация Apple и уровень AAA,
48 dp — Material Design.

## 12. Карусель и модальные окна: клавиатура и фокус

Наш сканер с axe регулярно находит «область прокрутки недоступна с клавиатуры» — это карусели.

Минимум для карусели:
```html
<section role="region" aria-roledescription="carousel" aria-label="Новинки">
  <div class="track" tabindex="0">…</div>
</section>
```
`tabindex="0"` на прокручиваемом контейнере даёт возможность листать его стрелками.
Кнопки «вперёд/назад» должны быть настоящими `<button>` с понятными подписями.

Минимум для модального окна:
- `role="dialog"`, `aria-modal="true"`, `aria-labelledby` на заголовок;
- фокус переходит внутрь при открытии и **возвращается на кнопку, которая его открыла**, при закрытии;
- Esc закрывает, Tab не уходит за пределы окна;
- фон становится неинтерактивным (`inert`).

Это ровно те места, где автоматика находит нарушение, а руками проверяется за минуту:
открыть окно клавишей, пройти Tab, закрыть Esc, посмотреть, куда вернулся фокус.

## 13. Мелкая цель нажатия — не всегда нарушение

Проверено 24.09.2026 на магазине заказчика. У критерия WCAG 2.5.8 (минимум 24×24 px, уровень AA)
пять исключений, и два из них срабатывают почти на каждом сайте:

- **строчная ссылка внутри предложения** — размер не нормируется вообще;
- **расстояние**: маленькая цель проходит, если круг диаметром 24 px вокруг неё
  не задевает соседнюю цель и круг вокруг другой маленькой цели.

Сравнивать одни центры нельзя: рядом может стоять большая кнопка, её центр далеко,
а край вплотную. В сканере считаем расстояние от центра маленькой цели до прямоугольника соседа.

Что это дало на деле: на главной магазина заказчика 11 целей меньше 24 px, нарушений уровня AA — **ноль**,
все проходят по расстоянию. На странице корзины из 12 мелких целей нарушение одно.

Вывод для писем клиенту: про мелкие цели говорим «меньше рекомендации Apple 44 pt»,
а слово «нарушение» ставим только рядом с числом `narusheniyaAA` из сканера.

## 14. Анимация: что проверяет сканер и чего он не видит

Добавлено 24.09.2026. В `scan.json` появилось поле `animaciya`:

- `dorogieSvoystva` — свойства, которые анимируются и при этом пересчитывают раскладку
  на каждом кадре. Плавно идут только `transform` и `opacity`.
- `uvazhaetNastroyku` — нашёлся ли в стилях блок `prefers-reduced-motion`.
- `stileyNeProchitano` — сколько таблиц стилей с чужих доменов прочитать не удалось.
  Если число не ноль, вывод неполный, и это надо говорить честно.

**Чего сканер не видит.** `document.getAnimations()` показывает только то, что бежит
прямо в момент съёмки. Переход по наведению в этот момент не бежит, поэтому одного этого
способа мало. Поэтому разбираются ещё и сами правила стилей: `transition-property`
и свойства внутри `@keyframes`.

**Отсев шума.** В первый прогон в список попали `--can-scroll` и `animation-timing-function`.
Теперь отбрасываются свои переменные, служебные свойства самой анимации
и вендорные приставки, а `visibility`, `color`, `box-shadow` и тени считаются дешёвыми.

**Что нашли на магазине заказчика:** анимируются `height`, `top`, `left`, `right`,
блок `prefers-reduced-motion` на сайте есть. В список из 12 пунктов заказа это не входит,
значит — отдельная задача с ценой, а не бесплатная добавка.

## 15. Замер без торможения врёт

Проверено 25.09.2026 на магазине заказчика. Наш сканер меряет на быстром домашнем интернете,
а покупатель смотрит с телефона в дороге. Разница большая:

| Показатель | без торможения | с торможением (`--tormoz`) | живой Chrome |
|---|---|---|---|
| LCP | 4,1–4,8 с | **5,84 с** | **5,79 с** |
| CLS | 0,000 | **0,061** | **0,061** |

Два независимых инструмента с торможением сошлись почти точно — значит, числа настоящие.

**Правило: клиенту называем числа с `--tormoz`.** Режим записывается в `scan.json`
полем `tormoz`, и отчёт печатает строкой, каким он был.

Условия торможения: задержка 150 мс, приём 1,6 Мбит/с, отдача 750 Кбит/с,
процессор в 4 раза медленнее. Это стандартный «медленный 4G» из инструментов Chrome.
